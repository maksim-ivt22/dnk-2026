```html GitHub Pages — Extra

GitHub Pages — Extra

Исправляем пути, создаём 404 и улучшаем опубликованный сайт

Задача

Основной сайт уже опубликован.

Теперь разберём несколько вещей, которые часто встречаются при настоящем деплое.

Нужно:
  1. проверить относительные пути;
  2. добавить страницу 404;
  3. добавить favicon;
  4. проверить обновление через push;
  5. посмотреть deployment в Actions.

1. Проверь относительные пути

Структура: 

site/

├── index.html
├── style.css
│
├── images/
│   └── game.jpg
│
└── pages/
    └── about.html

Из index.html: 

<img
    src="images/game.jpg"
    alt="Игра"
>

2. Путь из вложенной страницы

Мы находимся здесь: 

pages/about.html

Чтобы вернуться на главную: 

<a href="../index.html">
    Главная
</a>

.. означает: 

на одну папку выше

3. Подключение CSS из вложенной страницы

Если style.css находится в корне: 

<link
    rel="stylesheet"
    href="../style.css"
>
Это одна из самых частых проблем после публикации сайта.

4. Создай страницу 404

В корне проекта создай: 

404.html

Например: 

<!DOCTYPE html>

<html lang="ru">

<head>

    <meta charset="UTF-8">

    <title>
        Страница не найдена
    </title>

</head>

<body>

    <h1>
        404
    </h1>

    <p>
        Такой страницы не существует.
    </p>

    <a href="index.html">
        Вернуться на главную
    </a>

</body>

</html>

5. Проверь 404

После push попробуй открыть несуществующую страницу сайта.

Например: 

https://username.github.io/site/abc123.html

6. Добавь favicon

Добавь картинку: 

favicon.png

В <head>: 

<link
    rel="icon"
    href="favicon.png"
>

7. Добавь meta description

<meta
    name="description"
    content="Мой учебный сайт о компьютерных играх"
>

8. Добавь правильный title

Не: 

<title>
    Document
</title>

А: 

<title>
    Game Zone — Главная
</title>

9. Сделай новый commit

git add .

git commit -m "Добавил 404 и favicon"

git push

10. Посмотри Actions

Открой: 

GitHub
→ Repository
→ Actions

Найди deployment GitHub Pages.

Посмотри его состояние.

11. Что означает успешный deployment?

Если публикация прошла успешно, workflow будет завершён без ошибки.

12. Эксперимент с ошибкой

Временно измени путь к картинке: 

images/game.jpg

на неправильный: 

images/unknown.jpg

Сделай push и посмотри результат.

После эксперимента обязательно исправь путь и снова сделай commit + push.

13. Создай ссылку на исходный код

<a
    href="https://github.com/USERNAME/REPOSITORY"
    target="_blank"
>
    Исходный код проекта
</a>

14. Создай ссылку на опубликованный сайт в README

## Демо

https://username.github.io/repository/

Проверка

Проверены относительные пути

Использован ../ для вложенной страницы

Создан 404.html

404 опубликован

Добавлен favicon

Добавлен meta description

У страниц нормальные title

Проверен GitHub Actions

Сделано минимум одно обновление через push

README содержит ссылку на сайт

HARD — .nojekyll

Создай в корне проекта пустой файл: 

.nojekyll

Самостоятельно узнай, зачем он может использоваться при публикации статического сайта через GitHub Pages.

Подготовь короткое объяснение преподавателю.

SUPER HARD — собственный домен

GitHub Pages позволяет подключить собственный домен.

Например: 

myproject.ru

myproject.com

Самостоятельно найди в: 

Settings → Pages

раздел: 

Custom domain

Пока ничего покупать и подключать не нужно.

Нужно только понять:

  1. что такое домен;
  2. чем он отличается от github.io;
  3. где он подключается;
  4. что такое DNS.

ULTRA — сайт-портфолио

Создай новый репозиторий: 

USERNAME.github.io

Сделай в нём простую главную страницу: 

Имя

Обо мне

Мои технологии

Мои проекты

GitHub

Контакты

Опубликуй её через GitHub Pages.

В результате у тебя появится собственная страница разработчика.

Итог

После Extra ты умеешь:

  • публиковать сайт;
  • обновлять его через Git;
  • работать с относительными путями;
  • создавать 404;
  • добавлять favicon;
  • проверять deployment;
  • понимать назначение custom domain.
```
