Занятие №16 — GitHub Pages

Публикуем собственный сайт в интернете

GitHub Pages Deploy Hosting
Цель занятия: опубликовать HTML/CSS/JavaScript-сайт и получить настоящий адрес в интернете.

1. Что мы уже умеем?

На прошлом занятии мы научились:

  • создавать Git-репозиторий;
  • делать commit;
  • использовать push;
  • хранить проект на GitHub.

Но репозиторий на GitHub — это ещё не опубликованный сайт.

2. Что такое GitHub Pages?

GitHub Pages — сервис, который позволяет опубликовать статический сайт прямо из GitHub-репозитория.

HTML + CSS + JavaScript ↓
GitHub ↓
GitHub Pages ↓
сайт доступен в интернете

3. Какие сайты подходят?

GitHub Pages отлично подходит для:

  • HTML-сайтов;
  • CSS;
  • JavaScript;
  • портфолио;
  • лендингов;
  • учебных проектов.
GitHub Pages не запускает серверный Python, Django или PHP. Это статический хостинг.

4. Главный файл сайта

В проекте должен быть главный файл: 

index.html

Например: 

my-site/

├── index.html
├── style.css
├── script.js
└── images/
    └── photo.jpg
Для обычного HTML-сайта index.html должен находиться в корне публикуемой папки.

5. Сначала отправляем проект на GitHub

git status

git add .

git commit -m "Подготовил сайт к публикации"

git push

6. Открываем настройки Pages

На GitHub:

  1. открой репозиторий;
  2. открой Settings;
  3. в меню найди Pages;

7. Build and deployment

В разделе: 

Build and deployment

в Source выбери: 

Deploy from a branch

8. Выбираем ветку

Обычно: 

Branch: main

Папка: 

/(root)

Затем: 

Save
main ↓
/(root) ↓
Save ↓
GitHub Pages

9. Что означает /(root)?

Это корень репозитория.

Например: 

my-site/

├── index.html
├── style.css
└── script.js

Тогда выбираем: 

main
/(root)

10. Можно использовать папку docs

GitHub Pages также может публиковать сайт из папки: 

docs/

Например: 

project/

├── README.md
│
└── docs/
    ├── index.html
    └── style.css

Тогда в Pages выбираем: 

main
/docs

11. Получаем адрес сайта

После публикации GitHub покажет ссылку.

Обычно адрес проекта выглядит примерно так: 

https://USERNAME.github.io/REPOSITORY/

Например: 

https://maxdev.github.io/game-zone/

12. Особый репозиторий USERNAME.github.io

Можно создать репозиторий: 

USERNAME.github.io

Тогда адрес будет: 

https://USERNAME.github.io/

13. Что происходит после push?

После изменения проекта: 

git add .

git commit -m "Обновил главную страницу"

git push

GitHub Pages автоматически публикует новую версию.

изменили сайт ↓ commit ↓ push ↓ GitHub ↓ Pages обновляет сайт

14. Относительные пути

Очень важно правильно подключать файлы.

Хорошо: 

<link
    rel="stylesheet"
    href="style.css"
>

Картинка: 

<img
    src="images/game.jpg"
    alt="Игра"
>

15. Частая ошибка с путями

Для проекта GitHub Pages такая запись иногда приводит к проблеме: 

href="/style.css"

А такая обычно удобнее: 

href="style.css"
Для наших учебных сайтов используем относительные пути.

16. Ссылки между страницами

<a href="index.html">
    Главная
</a>

<a href="about.html">
    Обо мне
</a>

17. Если страница лежит в папке

site/

├── index.html
│
└── pages/
    └── about.html

С главной: 

<a href="pages/about.html">
    Обо мне
</a>

18. Ошибка 404

404 означает, что страница или файл не найдены.

Причины:

  • неправильный путь;
  • неправильное имя файла;
  • файл не загружен на GitHub;
  • index.html лежит не там;
  • ошибка в регистре букв.

19. Регистр букв важен

Это разные файлы: 

About.html

about.html

И: 

Images/photo.jpg

images/photo.jpg
На Windows ошибка регистра иногда незаметна локально, но после публикации сайт может сломаться.

20. Где смотреть ошибки публикации?

В GitHub можно открыть: 

Actions

Там отображается процесс публикации Pages.

21. GitHub Pages и секретные данные

Всё, что попало в опубликованный frontend, может увидеть пользователь.

Никогда не размещай в HTML или JavaScript пароли, секретные API-ключи и другие приватные данные.

22. Общая схема

VS Code ↓ git add . ↓ git commit ↓ git push ↓ GitHub repository ↓ GitHub Pages ↓ публичный сайт
