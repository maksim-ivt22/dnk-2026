Layout и компоненты

Результат занятия

Вы продолжите сайт учебного центра из первого занятия. Вынесете шапку и подвал в компоненты, добавите общую разметку раздела курсов и соберёте карточки из массива данных.

Понадобится проект school-site с TypeScript и App Router, запущенный на предыдущем занятии. Вспомните React-компоненты, props, массивы и map, а также маршруты / и /courses.

Дополнительное задание выполняется после основной работы и не входит в эти 180 минут.

Страница и общая разметка

В App Router файл page.tsx описывает содержимое конкретного маршрута. Файл layout.tsx задаёт общее оформление для своего раздела и вложенных маршрутов. Корневой app/layout.tsx обязателен и содержит элементы html и body.

app/
  layout.tsx          // общая разметка всего сайта
  page.tsx            // /
  courses/
    layout.tsx        // общая разметка раздела курсов
    page.tsx          // /courses
    web/
      page.tsx        // /courses/web

При открытии /courses/web корневой layout оборачивает layout раздела, а тот — страницу курса. Главная страница / находится вне папки courses и не получает layout раздела.

Зачем нужен children

В параметре children layout получает вложенную страницу или другую разметку. React подставляет это содержимое в место, где написано {children}.

import type { ReactNode } from 'react';

export default function CoursesLayout({ children }: { children: ReactNode }) {
  return (
    <div>
      <p>Раздел курсов</p>
      {children}
    </div>
  );
}

Этот пример предназначен для app/courses/layout.tsx: повторно добавлять в него html и body не нужно. Если забыть {children}, общий текст появится, а содержимое вложенных страниц не отобразится.

Layout раздела нужен для общего содержимого нескольких страниц раздела. Заголовок конкретной страницы и её основной текст остаются в соответствующем page.tsx.

Разделите страницу на компоненты

Компонент — функция React, возвращающая разметку. Её можно описать в отдельном файле, экспортировать и использовать в других компонентах. Например, шапку с навигацией можно подключить один раз в корневом layout.

import Link from 'next/link';

export default function SiteHeader() {
  return (
    <header>
      <Link href="/">Учебный центр</Link>
    </header>
  );
}

Чтобы карточки отличались содержимым, передавайте в них props. Пример с двумя строковыми свойствами:

type CardProps = {
  title: string;
  description: string;
};

function Card({ title, description }: CardProps) {
  return <article><h2>{title}</h2><p>{description}</p></article>;
}

// Внутри другой разметки:
<Card title="HTML" description="Создаём первую страницу" />

Если карточек много, удобно хранить данные в массиве и создавать элементы через map. Укажите стабильный key на элементе, который возвращает map, например уникальный идентификатор курса.

Стили компонента

В Next.js файл Card.module.css можно импортировать в компонент. Имена классов из CSS-модуля локальны для него, поэтому класс card не конфликтует с одноимённым классом из другого модуля.

/* Card.module.css */
.card { padding: 16px; border: 1px solid #94a3b8; }
import styles from './Card.module.css';

// В разметке компонента:
<article className={styles.card}>Карточка</article>

Для разметки React используйте className. Общие стили вашего проекта в app/globals.css и его импорт в корневом layout сохраняются.

Где выполняются компоненты

В App Router страницы и layout по умолчанию являются Server Components. Для статической шапки, текста и списка карточек на этом занятии достаточно серверных компонентов. Для состояния, обработчиков нажатия и браузерных API нужен Client Component: его файл начинается с 'use client'; до импортов.

Интерактивный компонент можно вложить в серверную страницу или карточку. Пример будет в дополнительном задании; для основной работы директива не требуется.

Самопроверка: где разместить подпись, общую только для /courses и /courses/web?

В app/courses/layout.tsx. Корневой layout добавит её и на главную, а только app/courses/page.tsx — не добавит на страницу /courses/web.
