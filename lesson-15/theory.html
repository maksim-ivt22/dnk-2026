Занятие №15 — Git и GitHub

Репозитории, commit, push и работа с историей проекта

Git GitHub 3 часа
Цель занятия: научиться сохранять историю проекта и загружать код на GitHub.

1. Зачем нужен Git?

Представим, что мы создаём сайт.

Сначала он работает. Потом мы изменили код и случайно всё сломали.

Можно делать так: 

site-final
site-final2
site-final-new
site-final-new2
site-final-really-final

Но это неудобно.

Git решает эту проблему.

Git хранит историю изменений проекта.

2. Что такое Git?

Git — система контроля версий.

Она позволяет:

  • сохранять изменения;
  • видеть историю проекта;
  • возвращаться к предыдущим версиям;
  • работать над проектом вместе;
  • отправлять код на GitHub.

3. Что такое GitHub?

Git и GitHub — не одно и то же.

Git ↓ работает с историей проекта
GitHub ↓ хранит Git-репозиторий в интернете

Git работает на нашем компьютере.

GitHub — сервис, где можно хранить репозитории онлайн.

4. Что такое репозиторий?

Репозиторий — папка проекта, за изменениями которой следит Git.

Например: 

my-site/

├── index.html
├── style.css
└── script.js

5. Проверяем Git

Открой терминал: 

git --version

Если Git установлен, появится его версия.

6. Имя пользователя

Git должен знать, кто делает изменения. 

git config --global user.name "Ваше Имя"

Email: 

git config --global user.email "ваш@email.com"
Эти команды обычно достаточно выполнить один раз на своём компьютере.

7. Создаём Git-репозиторий

Перейди в папку проекта.

Затем: 

git init

Git начинает следить за этой папкой.

8. git status

git status

Эта команда показывает:

  • какие файлы изменены;
  • какие файлы новые;
  • что готово к commit;
  • что ещё не добавлено.
git status — одна из самых полезных команд Git.

9. git add

После изменений нужно сказать Git, какие файлы мы хотим сохранить.

Один файл: 

git add index.html

Все изменения: 

git add .

10. Что такое commit?

Commit — сохранённая версия проекта.

изменили файлы ↓
git add . ↓
git commit ↓
версия сохранена

Команда: 

git commit -m "Первый commit"

Текст после -m — сообщение commit.

11. Хорошие сообщения commit

Лучше: 

git commit -m "Добавил меню"
git commit -m "Исправил стили карточек"
git commit -m "Добавил форму"

Хуже: 

git commit -m "что-то"
git commit -m "123"
git commit -m "изменения"

12. История commit

git log

Git покажет историю сохранённых версий.

13. Основной рабочий цикл Git

изменил код ↓
git status ↓
git add . ↓
git commit -m "Описание" ↓
продолжаем работу

14. Теперь GitHub

На GitHub создаём новый репозиторий.

Например: 

my-first-site

После создания GitHub покажет адрес репозитория.

15. Связываем локальный проект с GitHub

Добавляем удалённый репозиторий: 

git remote add origin АДРЕС_РЕПОЗИТОРИЯ

Например: 

git remote add origin https://github.com/username/my-first-site.git

16. Основная ветка

git branch -M main

Мы называем основную ветку: 

main

17. Первый push

git push -u origin main

После этого код появится на GitHub.

наш компьютер ↓ git push ↓ GitHub

18. Следующие push

После первого раза обычно достаточно: 

git add .

git commit -m "Добавил новый раздел"

git push

19. Что такое push?

push отправляет наши commit в удалённый репозиторий.

Commit сохраняет изменения в Git на компьютере.

Push отправляет эти commit на GitHub.

20. Что такое clone?

Если проект уже находится на GitHub, его можно скачать через Git: 

git clone АДРЕС_РЕПОЗИТОРИЯ

Например: 

git clone https://github.com/username/my-first-site.git

21. Что такое pull?

pull получает новые изменения из удалённого репозитория. 

git pull
GitHub ↓ git pull ↓ наш компьютер

22. Основные команды занятия

git init

git status

git add .

git commit -m "Сообщение"

git log

git remote add origin ...

git branch -M main

git push -u origin main

git push

git pull

git clone ...

23. Не загружаем лишнее

Некоторые файлы не нужно отправлять в Git.

Для этого существует: 

.gitignore

Например для Node.js: 

node_modules/
Папку node_modules обычно не загружают на GitHub.

24. Быстрая проверка

Что такое Git?
Чем Git отличается от GitHub?
Что делает git status?
Для чего нужен git add?
Что такое commit?
Что делает git push?
Что делает git pull?
Что делает git clone?

Итог

Основная схема:

изменение
↓ git add .
↓ git commit
↓ git push
↓ GitHub
