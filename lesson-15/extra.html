```html Git и GitHub — Extra
Git и GitHub — Extra

Clone, pull, ветки и работа с отдельной версией проекта

Задача

Основной проект уже находится на GitHub.

Теперь попробуй несколько возможностей, которые используются в реальной разработке.

Нужно:
  1. склонировать репозиторий;
  2. создать новую ветку;
  3. сделать изменение в новой ветке;
  4. создать commit;
  5. переключиться между ветками;
  6. получить изменения через pull.

1. Clone

Создай отдельную папку, не внутри текущего проекта.

В терминале выполни: 

git clone АДРЕС_РЕПОЗИТОРИЯ

Например: 

git clone https://github.com/username/my-web-project.git

2. Открой склонированный проект

Перейди в папку: 

cd my-web-project

Проверь: 

git status
Репозиторий уже настроен. Повторно выполнять git init не нужно.

3. Посмотри remote

git remote -v

Ты увидишь адрес GitHub-репозитория.

4. Что такое ветка?

Ветка позволяет делать изменения отдельно от основной версии. 

main
 |
 |---- feature-about

5. Посмотри ветки

git branch

6. Создай новую ветку

git switch -c feature-about

Проверяем: 

git branch
Звёздочка рядом с названием показывает текущую ветку.

7. Сделай изменение

Добавь на сайт новый раздел, например «О проекте». 

<section>

    <h2>
        О проекте
    </h2>

    <p>
        Этот раздел создан
        в отдельной Git-ветке.
    </p>

</section>

8. Сохрани изменение

git add .

git commit -m "Добавил раздел о проекте"

9. Сравни с main

Переключись: 

git switch main

Открой файл.

Новый раздел должен исчезнуть.

10. Вернись в feature-about

git switch feature-about

Раздел снова появится.

Теперь видно, зачем нужны ветки: разные версии проекта могут существовать отдельно.

11. Отправь ветку на GitHub

git push -u origin feature-about

Открой GitHub и проверь появление новой ветки.

12. Pull

Вернись: 

git switch main

Получи последние изменения: 

git pull

13. git diff

Измени любой файл, но пока не делай commit.

Выполни: 

git diff

Git покажет, что именно изменилось.

14. Отмена локального изменения

Измени строку в файле специально для эксперимента.

Затем: 

git restore ИМЯ_ФАЙЛА

Например: 

git restore index.html
Проверь, что несохранённое изменение исчезло.

15. Полезные команды

git branch

git switch main

git switch -c new-branch

git remote -v

git diff

git restore index.html

git pull

git clone ...

Проверка

Репозиторий склонирован

git init повторно не использовался

Проверен git remote -v

Создана новая ветка

В новой ветке сделано изменение

Создан commit

Выполнено переключение между ветками

Ветка отправлена на GitHub

Использован git pull

Использован git diff

Проверен git restore

HARD — Pull Request

Открой GitHub.

Найди свою ветку: 

feature-about

Создай Pull Request из этой ветки в: 

main

В описании напиши, какие изменения были сделаны.

После этого посмотри, какие файлы GitHub показывает как изменённые.

SUPER HARD — Merge

После проверки Pull Request объедини ветку с main.

Затем локально: 

git switch main

git pull

Проверь, что изменения из новой ветки появились в main.

Итог

После Extra ты уже знаком с:

  • clone;
  • pull;
  • remote;
  • ветками;
  • switch;
  • diff;
  • restore;
  • Pull Request;
  • merge.
```
